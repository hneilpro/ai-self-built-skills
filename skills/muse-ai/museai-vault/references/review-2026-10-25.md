# Critic review — MuseAI-Vault skill series, the original build

Role: critic, read-only pass first, then a single revision round
by the builder. This review is recorded in the branch, as required.
It does not claim a push, a merge, or a live GitHub state.

## What passed on first read
- Structure mirrors the repo's vpn series: one parent orchestrator
  plus three component skills, SKILL.md frontmatter with snake_case
  names and trigger descriptions, detail in references/.
- Order is internally consistent: Oracle, then OpenBao, then tunnel,
  then Access, then CA swap, then per-AI tokens, then sign, SSH,
  board check-in, with Route C as a variant, not the default.
- No owner real name, no email, no real IP, tunnel ID, CA
  fingerprint, public key, or token value in any file. The only
  token-like pattern is the labelled fake Vault token example.
- User commands are single-line. The only user command in the
  series is the single-line CA copy command in the recovery
  runbook. No fenced multi-line blocks, no heredocs.
- Route C is correctly scoped: separate Bypass application for
  one sign path only, Vault 403 without a token, rest stays
  protected, single-header mode correctly rejected as a fix for a
  single-surrogate limit.
- Board rules are correctly stated: reply not new thread, usage
  refreshed same edit, timestamp matches, gating bands.

## Issues found, and fixes made in revision round 1
1. Cross-skill reference ambiguity: the OpenBao skill cited the
   parent recovery runbook as a bare `references/` path, which
   resolved to the wrong skill directory in a naive check. Fixed
   to the full `muse-ai/museai-vault/references/recovery-runbook.md` path.
   The parent skill's Cloudflare reference was already a full
   path and was left as is.
2. User protocol was correct in principle but lacked a concrete
   worked sequence. Fixed: a three-message, one-at-a-time CA swap
   sequence was added to `user-one-step-protocol.md`, with an
   explicit "never send all three together" warning.
3. Trial-end check was generic. Fixed: the known trial-end date
   from the original rebuild, the trial end date, is now recorded in
   `../../museai-vault-oracle/references/oracle-setup.md` as "known at writing", with the same check
   applying to any future trial-end date.
4. OpenBao listeners were described without ports. Fixed: public
   TLS port 8200 and localhost 127.0.0.1:8201 are now stated in
   the OpenBao skill, with the health endpoint
   `/v1/sys/health` checked from inside the vault server.
5. Board check-in category was unstated. Fixed: the verification
   checklist now notes future check-ins use the current rebuild post's
   category and topic, not a copied old topic.
