7. Risk — PASS with notes. Biggest residual risks are disclosed: heuristic

## Findings
### N1 (Minor) — identity measured before upscale
The gate verifies the pre-upscale pixels; ESRGAN does not move identity
materially, and the shipped file is the upscaled one. Acceptable; noted so
nobody later "fixes" it by adding a second slow verification by default.

### N2 (Minor) — candidate_modes mutates a.face_mode on Flux
Forcing an SDXL mode to local-swap on a Flux checkpoint rewrites the arg
object. Harmless in the single-run CLI, but it makes
face_mode_requested report the rewritten value. Follow-up if it ever
matters: compute the effective mode without mutation.

### N3 (Minor/opinion) — verify+swap reloads InsightFace twice
Two subprocess calls, ~10s each locally. Fine for one-image generations;
revisit only if batch work appears.

## Verdict: approve with notes
Notes are N1-N3 (none blocking) plus the standing unverified live GPU run.
Nothing here counts as independent approval; the owner's fresh-tunnel run
is the real second check.

## Revision round 1 (critic, after owner correction)
The owner's visual check caught what the metric missed — exactly the
failure class this gate exists for. Two overclaims in the original build:
(1) "0.92, clean, no artifacts" from a thumbnail view, never checked at
full zoom against the owner's actual reference; (2) a 0.55 pass bar that
near-lookalikes (0.58-0.60) clear. Builder fixes verified in the test
report addendum: threshold 0.65, restoration with measured sharpness,
blur reporting, corrected proof at 0.884 / sharpness 108.5. Rows 5 and 7
re-scored PASS within local scope; live GPU scope unchanged (unverified).
Lesson banked: a similarity score is a gate, never a likeness claim —
the human visual check against the owner's reference is the acceptance
test, and proofs get viewed at full resolution before they ship.

v4 correctly stops polishing the swap (its geometry ceiling) and moves
the real fix to in-diffusion identity: averaged-template sources,

template proof (0.72 vs canonical) must not be presented as "her" — it
is progress on sharpness only, and the review requires the LoRA/live
run before any likeness claim. Verdict stays approve-with-notes for the
tooling; likeness itself remains UNVERIFIED until the 4090 work runs.
